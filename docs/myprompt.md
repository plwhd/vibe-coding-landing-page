## AI 根据 prompt 生成网页v1.1

## 设计师：
  1.  面对AI生成的网页。我发现其中存在一些优劣。那么，我应该以什么样子的目标去让 AI 进行调整呢。比如说网页的目标、视觉的目标。以及视觉上有很多可以进行优化的点。比如色彩、字体、节奏等。应该按照什么样子的顺序/主线呢。用户体验五要素理论在此过程中是否可以借鉴？
  2. 那么，对于提供给 AI的prompt 是什么？希望让AI 按照这个规范自己首先调整一遍。
##  AI prompt：
  - 请基于当前项目，先完整审视现有 Vite + React + Tailwind 活动页，然后按照“用户体验五要素”对页面进行第一轮自我优化。

项目目标：
这是七牛云 2026 校招季活动页，页面类型是科技公司校招 / AI 项目实战挑战赛 / 招聘活动页。核心目标是让 2024-2026 届学生快速理解活动价值，并点击“上传简历并报名”。

请按照以下顺序调整，不要只做表层美化：

1. 战略层
- 明确页面第一目标：报名转化。
- 明确用户第一判断：我是否适合参加、是否值得报名。
- 首屏必须突出：2026 七牛校招季、SSP Offer、50000 奖金、AI 项目实战、上传简历并报名。
- 次级信息不要抢主 CTA。

2. 范围层
- 保留并强化：100+ Offer、开放岗位、活动流程、五个实战议题、奖项设置、评审规则、加入七牛。
- 压缩或后置：推荐报名、AI Token 福利、二维码、长规则、获奖队伍。
- 岗位、议题、流程必须便于快速扫描。

3. 结构层
请优化页面叙事顺序：
- 首屏 Hero
- 活动亮点
- 开放岗位
- 活动流程
- 实战议题
- 奖项设置
- 评审与提交规则
- 获奖队伍
- 加入七牛
- 底部 CTA 与二维码

4. 框架层
- 检查每个模块的布局是否服务于阅读和转化。
- CTA 需要在首屏、关键模块、底部和移动端持续可达。
- 卡片 hover 可以有轻微位移和光泽，但不要过度。
- 时间线需要更清晰，避免日期信息堆叠。
- 移动端必须完整可用，避免文本溢出、按钮拥挤、浮动按钮遮挡内容。

5. 表现层
视觉方向：
- 浅色系、现代、年轻、科技感、AI 感。
- 避免传统企业官网感。
- 避免廉价赛博风、过度霓虹、过度渐变。
- 色彩控制在一个主蓝色、一个辅助青绿色、少量暖色奖励点缀。
- 字体层级要稳定：首屏标题强，中段标题克制，正文易读。
- 页面节奏要有强弱变化，不要所有模块都像同一种卡片。

具体优化要求：
- 先审查现有页面中视觉、信息层级、节奏、移动端体验的问题。
- 然后直接修改代码，不要只给建议。
- 内容必须继续从结构化数据中渲染，不要把大段内容硬编码到 JSX。
- 保持 Vite + React + Tailwind CSS 技术栈。
- 保持组件拆分清晰。
- 不依赖后端。
- 不删除已有核心内容。
- 不引入沉重复杂的新依赖。
- 修改后运行 npm run build，确保构建通过。

验收标准：
- 用户进入首屏 3 秒内能知道这是七牛云校招 AI 实战活动。
- 用户能明确看到报名 CTA。
- 用户能快速理解活动价值、岗位、流程、议题、奖项。
- 页面视觉更统一、更高级、更适合 AI / 云计算 / 开发者 / 校招场景。
- 桌面和移动端都没有明显拥挤、溢出、遮挡。
- npm run build 通过。

## AI：
请只针对表现层做一轮视觉优化，不改变页面核心结构和内容。

请按以下顺序审视并修改：

1. 视觉定位
确认页面是否符合“浅色、现代、年轻、科技感、AI 感、校园招聘”的气质。
避免传统企业官网、廉价赛博、过度霓虹、过度渐变。

2. 视觉主线
检查页面是否有强弱节奏：
首屏强冲击，中段清晰扫描，规则区收敛，底部 CTA 再次强化。
不要让所有模块都像同一种卡片。

3. 色彩系统
统一颜色使用：
- 主色：蓝色，用于 CTA、重点数字、当前状态
- 辅助色：青绿色，用于 AI、完成、前沿感
- 强调色：暖色，只用于奖金、奖项、关键激励
- 中性色：用于正文、边框、卡片背景
减少不必要的渐变和发光效果。

4. 字体字号层级
检查 H1、H2、H3、正文、标签的层级是否稳定。
首屏标题可以强，中段标题要克制，正文要易读。
移动端避免标题过大导致断行难看。

5. 文本密度
压缩首屏和卡片里的长句。
卡片只保留摘要，长规则进入折叠或弹窗。
确保用户 3 秒内能理解页面价值。

6. 布局节奏
优化模块间距、卡片密度、留白和左右结构。
让页面有呼吸感，不要每一屏都同样拥挤。

7. 组件质感
统一卡片圆角、边框、阴影、hover。
CTA 按钮权重要最高，普通卡片更轻，规则区更克制。

8. 移动端体验
检查移动端首屏、CTA、卡片、时间线、浮动按钮。
避免溢出、拥挤、遮挡和难读。

请直接修改代码。
不要引入重型新依赖。
不要删除核心内容。
修改后运行 npm run build，确保通过。
