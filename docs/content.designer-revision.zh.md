### 1.8 议题介绍

#### 议题一：文本或图片生成 3D 模型

开发一个根据文本或图片生成 3D 模型的应用，要构建的 3D 模型只需要实现单个素材元素的生成，不需要到场景级别（例如能生成一匹马，而不需要一匹马在草原奔跑）。

需回答：目标用户与用户故事；APP 功能与优先级；3D 模型生成 API 选择与对比；3D 模型生成效果评估指标和评估系统设计；减少第三方 3D 模型生成 API 调用次数的方法。

提交要求：开发 APP，包括效果评估系统以及模型调用频次优化功能，并将 1-5 点思考整理成文档作为作品说明提交。

设计师调整建议：前台卡片只展示一句话摘要，完整问题放入详情弹窗或锚点页。

#### 议题二：AI 角色扮演网站

开发一个利用 AI 来做角色扮演的网站，用户可以搜索自己感兴趣的角色例如哈利波特、苏格拉底等并可与其进行语音聊天。

需回答：目标用户与痛点；APP 功能与优先级；LLM 模型选择与对比；AI 角色除语音聊天外还应具备的技能。

提交要求：开发 APP，实现 3 个以上 AI 角色应该具备的技能。不能调用第三方 Agent 能力，只允许调用 LLM 模型、语音识别以及 TTS 能力，并将 1-4 点思考整理成文档。

设计师调整建议：可用“角色搜索 / 语音对话 / 技能扩展”三个标签帮助用户快速理解。

#### 议题三：ESP32 智能小车

设计一个基于 ESP32 或其他嵌入式芯片的智能小车，融合超声避障、颜色寻路、相机视觉功能，实现「沿指定颜色路径行驶 + 遇障主动避障+视觉辅助感知」的自主移动任务。支持扩展 WiFi 图像传输、多传感器数据融合等进阶功能。

硬件清单：超声波传感器、颜色传感器、电机驱动板、相机模块（可选）。

基础功能：硬件连接与初始化；超声避障；颜色寻路。场景为 1cm 宽黑色胶带构建的半径约 1m 圆圈，圆圈可能不连续并存在不超过 10cm 的障碍物，小车需从起点绕行一圈回到起点。

加分功能：视觉辅助路径识别；WiFi 实时图像传输；多传感器数据融合决策；增加其它有特色的功能并说明用户收益。

设计师调整建议：该议题文本最长，建议拆成“必做 / 加分 / 硬件”三栏，减少阅读压力。

#### 议题四：小说生成漫画

开发一个根据一篇小说生成相应漫画的应用。

需回答：目标用户、痛点和用户故事；实现挑战与应对；AIGC API 选择与对比；未来规划功能及其重要性。

提交要求：开发应用。不能调用第三方 agent 能力，只允许调用 LLM、各类 AIGC 模型和语音 TTS 能力，并将 1-4 点思考整理成文档。

设计师调整建议：可把该议题定位为“文本理解 + 分镜 + 图像生成”的创意类挑战。

#### 议题五：语音对话控制电脑

基于大模型开发一个用语音对话的方式来控制你的电脑的应用，比如播放音乐、写一篇文章等，甚至让大模型能够组合这些能力实现复杂的场景。

需回答：产品功能与优先级；实现挑战与应对；LLM 模型选择与对比；未来规划功能及其重要性。

提交要求：开发应用。不能调用第三方 agent 能力，只允许调用 LLM 模型、语音识别以及 TTS 能力，并将 1-4 点思考整理成文档。

设计师调整建议：可突出“语音入口 + 电脑控制 + 复杂任务编排”，与 Agent 概念保持边界说明。

### 1.9 评审与提交规则

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 用户价值 | 60% | 产品目标合理性、产品设计合理性、功能丰富度、是否符合用户需求等 |
| 技术质量 | 40% | 架构设计（设计思路的清晰度与合理性、可维护性可扩展性）、代码质量（健壮度-代码逻辑、代码规范、可复用性与可读性）等 |

作品提交规则：

- 作品需符合本次议题方向的要求。
- 请确保团队及个人提交的作品是自主完成的。
- 作品提交截止时间：首批截止时间为 2025 年 09 月 28 日 23:59。
- 提交方式：请将产品所有源代码、如何运行程序的说明、架构设计文档（包含模块规格、分工）、录制的 demo 视频上传至 GitHub、Gitee 或其他开源协作平台。
- 组队投递情况下，代码仓库需要有多人代码提交记录。如果代码仓库只有一个人提交代码的痕迹，将视为个人作品。
- 如果是组队完成作品，出于工程规范要求请同学们基于 pull request 提交每一次的变更。
- 代码仓库需要保留开发期间团队协同创作或个人创作的所有过程痕迹。只在最后一天一次性提交代码亦视为不合格，将无法获得路演资格。

知识产权与学术诚信：

- 除另行说明，作品的知识产权归提交队伍或个人所有。
- 不得侵犯他人知识产权或其他权益，不得未经相关单位许可公开发布涉及该单位知识产权的作品及软件。
- 如造成不良后果，相关法律责任由提交人自行承担，七牛云不负任何法律责任。
- 一经确认代码抄袭或技术抄袭等学术不端行为，或代码重复率在 50% 以上，将取消路演资格，并列入招聘黑名单。
- 默认报名参与此次招聘活动的同学同意七牛云公开作品源代码。七牛云拥有免费使用投递作品进行演示和出版的权利（不涉及技术细节）。如果以盈利为目的使用投递作品，需与作品归属队伍或个人协商，经同意后签署相关作品使用的协议。

设计师调整建议：规则内容信息密度高，建议采用“评审权重卡片 + 提交清单 + 折叠法律声明”的组合。

## 4. 每个模块的设计目标

### 4.1 首屏 Hero

- 设计目标：在 3 秒内让用户知道这是七牛云 2026 校招活动，并形成“高奖金、高 Offer 等级、项目实战”的强记忆点。
- 关键内容：2026 七牛校招季、产研专场盛启、SSP Offer、50000 元奖金、报名 CTA。
- 交互目标：点击报名或向下滚动查看活动详情。
- 设计师调整建议：使用更强的校招视觉主角和技术挑战感，避免只像普通招聘 Banner。

### 4.2 资格与亮点信息条

- 设计目标：快速回答“我能不能参加、这个活动有什么关键利益点”。
- 关键内容：2024-2026 届毕业生及在读学生、线上、100+ offer、项目实战。
- 交互目标：无强交互，作为首屏下方信息确认。
- 设计师调整建议：可以做成 4 个紧凑信息块，不要写成长段说明。

### 4.3 奖项与福利

- 设计目标：强化参与动机，把“奖金”和“SSP Offer”从首屏承接下来。
- 关键内容：一等奖 ¥50000、二等奖 ¥10000、三等奖 ¥2000、创作奖 ¥500、报名成功 Token / 代金券权益。
- 交互目标：引导继续查看参与流程。
- 设计师调整建议：奖项金额要视觉优先，Token/算力福利作为补充，不要抢过主奖金信息。

### 4.4 开放岗位

- 设计目标：让不同方向学生快速判断岗位匹配度。
- 关键内容：11 个岗位、城市、100+ offer。
- 交互目标：选择岗位或进入报名。
- 设计师调整建议：如果补全岗位职责，可支持“技术 / 产品 / 业务 / 运营”分组筛选。

### 4.5 活动流程

- 设计目标：降低报名和参赛的不确定性，让用户理解时间节奏。
- 关键内容：报名、回执、解锁议题、提交作品、路演终面、Offer 发放、获奖公布。
- 交互目标：推动用户在看到清晰路径后报名。
- 设计师调整建议：两批次时间建议用上下两条时间线或标签切换，不要把日期堆在每个节点内。

### 4.6 实战议题

- 设计目标：展示活动含金量，让技术型用户感到议题真实、有挑战、有发挥空间。
- 关键内容：3D 模型生成、AI 角色扮演、ESP32 智能小车、小说生成漫画、语音控制电脑。
- 交互目标：点击查看详情，选择感兴趣议题。
- 设计师调整建议：每个议题卡片建议包含“方向标签 + 任务摘要 + 详情入口”，详情内再展示完整问题。

### 4.7 评审与提交

- 设计目标：建立公平、专业、可执行的参赛标准。
- 关键内容：用户价值 60%、技术质量 40%、提交材料、PR 协作要求、知识产权和学术诚信。
- 交互目标：帮助用户判断提交标准和准备材料。
- 设计师调整建议：把规则拆为“评分标准 / 提交材料 / 不合格情形 / 法律声明”四块。

### 4.8 获奖队伍

- 设计目标：增强活动可信度，并为复盘页面提供结果展示。
- 关键内容：一等奖、二等奖、三等奖、创作奖队伍和议题方向。
- 交互目标：浏览结果；如有作品链接可进一步查看。
- 设计师调整建议：当前只展示队伍名称和方向，若能补充作品链接或 Demo 封面，视觉价值会明显提升。

### 4.9 加入七牛

- 设计目标：把活动从“比赛/招聘”转化为“为什么值得加入七牛”的雇主品牌叙事。
- 关键内容：覆盖全国 99% 网民、云到 AI 到具身智能、SSP Offer、公司数据、客户案例、灵矽AI平台。
- 交互目标：增强投递意愿。
- 设计师调整建议：公司介绍长段落建议拆成数据点和品牌叙事，不要使用大段正文。

### 4.10 推荐与资源活动

- 设计目标：承接已报名用户的扩散和开发资源需求。
- 关键内容：推荐报名奖品、有效报名定义、AI 推理 Token 奖励、算力好礼。
- 交互目标：复制推荐链接、查看规则、参与 AI 推理活动。
- 设计师调整建议：这是辅助转化模块，建议放中后段或页脚前，避免稀释主报名目标。

### 4.11 页脚行动区

- 设计目标：提供最后一次联系和关注入口。
- 关键内容：七牛云公众号、扫码进群、1024 实训营。
- 交互目标：扫码关注、进群咨询。
- 设计师调整建议：三个二维码建议配明确用途说明，例如“关注动态 / 咨询报名 / 训练营入口”。

### 4.12 浮动操作

- 设计目标：让高频动作始终可达。
- 关键内容：上传简历并报名、扫码进群、算力好礼、回到顶部。
- 交互目标：提高报名和咨询转化。
- 设计师调整建议：移动端建议压缩为底部单 CTA + 次级菜单，避免浮动按钮遮挡内容。
